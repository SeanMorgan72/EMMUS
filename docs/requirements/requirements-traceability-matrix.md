# Requirements Traceability Matrix

This matrix is the authoritative traceability baseline for EMMUS. Each requirement is mapped to implementation evidence and the applicable verification evidence from the unit, integration, and system test suites.

## Traceability legend

- Status values: `Implemented`, `Partially implemented`, `Verified`, `Partially verified`, `No automated coverage`.
- Evidence is mapped at the file level to preserve maintainability and ease of review.
- Coverage gaps are recorded explicitly so that project evaluation can distinguish verified behavior from planned work.

## Coverage summary

The current traceability baseline shows that the majority of implemented memory-management functionality has direct unit/integration evidence. The primary gap is the absence of a populated system-test layer for end-to-end validation: [tests/system](../../tests/system) is empty.

### Current verified areas

- PageTable and PhysicalMemoryManager integration
- MMU page-fault and invalid-access behavior
- FIFO, LRU, and factory policy logic
- Core memory access semantics

### Outstanding gaps

- System-level verification for workload execution and algorithm comparison
- Process manager and simulation lifecycle verification
- Dedicated review artifacts for all future user stories
- Automated documentation workflow checks for traceability updates

## Traceability maintenance rule

When a requirement changes, the owner must update the corresponding row in this matrix and the review evidence file before the change is considered complete.
